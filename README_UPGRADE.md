# Updating to QAVF 0.7.2

This archive contains the complete updated source tree, tests, scripts, and
documentation. It is a source delivery, not a claim of publication to PyPI or
successful execution of every remote release gate.

Version 0.7.2 addresses the comprehensive 0.7.1 review: input-safe report
publication, bounded batch coalescing, enforced spill-writer lifetime, accurate
input protocols, safe optional-module admission, focused reader dependencies,
shared column outcomes, and shorter SQLite allocation-lock scope.
See [the implementation record](docs/review_072_implementation.md) and
[the current validation results](validation/review_072/README.md). Older validation
records remain historical and do not certify this update.

## Replace your local checkout

1. Back up your current checkout, especially locally edited configuration, plugins,
   input data, and output reports.
2. Extract this ZIP into the project root that contains `pyproject.toml`. Do not
   extract it into the inner `qavf/` package directory. Prefer a new directory and
   copy your own configuration and plugins into it after checking the changes.
3. Use Python 3.12 or newer and a virtual environment. From the project root run
   `python -m pip install -e ".[all]"`. For core-only operation use
   `python -m pip install -e .`; optional statistical/spatial operations need their
   documented extras. With uv available, `uv sync --locked --all-extras` installs
   the locked development environment, including test tools.
4. Run `python -m pytest`. If using uv, use `uv run --locked --all-extras python -m pytest`.
   Live service tests require the documented explicit service configuration.
5. Run your own representative QA contracts and compare outcomes before replacing
   production jobs. Corrected false passes may now become failures or incomplete
   assessments; do not loosen limits just to restore the old status.

The archive contains no virtual environment, generated bytecode, or test caches.
See `UPDATE_MANIFEST.json` for added, changed, and removed paths against the
exact 0.7.1 ZIP reviewed for this update. Overwriting cannot remove stale files: if its removed list is
nonempty, remove those paths or use a clean extraction.

## Compatibility notes

- DuckDB now requires version 1.3.0 or newer. Version 1.2 loses timezone metadata
  when inferring zoned CSV timestamp types, even with ICU loaded. Native probes
  and the existing CSV timezone regression establish correct behavior in 1.3.0
  and 1.4.0. Installing this update resolves the corrected minimum automatically.
- Existing `validate`, `compare_datasets`, runner, descriptors, and plugin APIs
  remain available. `qavf.engine.registry.RuleParams` is a compatibility alias
  for the neutral `qavf.parameters.RuleParams` contract.
- Result models now expose `affected_count_exact` (default `True`). A saturated
  CSV diagnostic count is a lower bound (`False`), displayed as “at least” in HTML.
  A lower bound above the permitted rejection threshold is sufficient to fail;
  one at or below it is insufficient to pass and is reported incomplete.
- File sources accept positive `rejects_budget` (default 1000 raw native error
  entries). Multiple errors may describe one rejected line. A native
  `rejects_limit=0` no longer authorizes unlimited diagnostics. Increase the
  explicit budget for more complete diagnostics; insufficient budgets remain
  visible. Very wide error strings still consume backend-dependent memory.
- New `BatchSource` owns a context-managed batch factory and a declared schema.
  It uses a coherent admitted snapshot and closes on success or failure. Live
  factories are for in-process execution; cancellation cannot interrupt arbitrary
  blocking Python callbacks. See [input ownership](docs/input_ownership.md).
- `explain(...)` reads configuration but does not read input datasets. Unknown
  schema, row counts, physical reads, and native memory remain unknown. Plugin
  imports require explicit `load_plugins=True` for planning.
- Optional profiles require explicit QA contracts. `regression` and `change`
  additionally require their configured baseline/comparison rules. Existing
  specialized comparison levels retain their scope: unchanged coordinates do not
  prove valid geography, and common-group relationships do not prove coverage.
- Crosswalks support primary-style descriptors in direct in-process use.
  Serializable run configuration uses named datasets with `crosswalk.dataset`
  for frames, loaders, or queries; nested live `crosswalk.data` is rejected with
  guidance. Arbitrary live handles are not silently serialized or transported.
- Exact Sen slopes have explicit pair/byte admission. No approximate statistic
  or sampled validation silently replaces exact work when resources are exhausted.
